## Preserved release-wrapper failures

The first clean-clone wrapper created and detached the correct clone but set
PowerShell's error preference so strictly that ordinary `unittest -v` output
on the native stderr stream raised `NativeCommandError`. The first displayed
test had status `ok`; no test process returned failure and no artifact was
changed. The corrected wrapper reused that still-clean clone, checked its
head and status again, and handled native commands by exit code. The complete
replay then passed.

Before the clone run, a first Markdown-link wrapper mistook PowerShell type
casts such as `[int64](...)` in the status audit for Markdown links. It reported
two arithmetic expressions as missing paths. The corrected parser excludes
non-link arithmetic syntax and then checked every tracked Markdown file
successfully. This was a validation-parser false positive, not a missing
repository reference.

The independent status report initially contained temporary download paths in
its uncommitted run record. Integration replaced them with neutral temporary
filenames while retaining the public source URLs, source hashes, and the fact
that the copies were ephemeral. No machine-local path entered Git history.
