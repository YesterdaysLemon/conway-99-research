# Wave 22 full-seven-deck failed runs

All failures are retained because solver messages, timeouts, and harness
behavior are not mathematical certificates.

## Orchestrator scratch harness: importlib/dataclass

The first scratch import loaded a Python module with
`importlib.util.module_from_spec` but did not insert the module into
`sys.modules` before executing it.  The imported module used `@dataclass`, whose
annotation processing then crashed because it could not resolve the module
namespace.  This was a harness defect, not evidence about the deck system.
Later scratch imports either registered the module first or used ordinary
module imports.

## Orchestrator scratch algebra: two HNF attempts

The first SymPy Hermite-normal-form attempt computed a matrix rank and then
timed out after 120 seconds.  A second HNF attempt was manually terminated
after several minutes without an answer.  Neither attempt produced an HNF,
Smith form, lattice certificate, or mathematical conclusion.

The exact finite-field ranks found in that scratch route were

```text
p=2: 48
p=3: 57
p=5: 61
p=7: 61
```

No restriction on `t=n3/3` modulo any of those primes was found.  The present
standard-library checker independently reproduces those four ranks and also
finds rank 62 over `F_11`, proving real row rank 62.  This rank statement does
not certify integer feasibility by itself.

## Combined Hamiltonian MILP: false infeasibility

The first committed discovery-script form used a nonconstant arbitrary
objective and appended the redundant equation
`sum(x)=binom(99,7)` to the 62 deck equations.  On the badly scaled floating
model, SciPy/HiGHS returned:

```text
status=2
The problem is infeasible.
(HiGHS Status 8: model_status is Infeasible; primal_status is None)
```

That result was rejected because there was no exact infeasibility certificate.
Using a zero objective and only the 62 nonredundant deck equations produced an
integral candidate at the same fixed values `n3=705`, `h11=2820`.  The maximum
floating-to-integer rounding discrepancy was about `1.2e-7`, after which the
candidate passed all equations using standard-library integer arithmetic.  The
failed solver result is therefore demonstrably a numerical/harness failure.

## Final artifact-validation harness

An initial combined replay command was rejected before execution because it
tried to delete a computed temporary path in the same PowerShell command.  The
replay was rerun to an explicit fixed temporary path without deletion and
passed byte-for-byte.

The first `rg` hygiene pattern also failed before scanning because the
PowerShell/regular-expression escaping left an unclosed group.  A
standard-library Python scan with two separately compiled patterns then passed.
Two PowerShell attempts to remove generated `__pycache__` files were blocked by
the command policy, and `apply_patch` correctly refused to decode the binary
`.pyc` files as UTF-8.  A path-checked Python cleanup removed exactly the two
generated bytecode files and their now-empty directory.  None of these harness
failures touched the mathematical artifacts.
